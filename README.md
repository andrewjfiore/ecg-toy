# ECG Trainer

A self-contained, offline 12-lead ECG trainer. Practice cases are **synthetic**, generated by a parametric sum-of-Gaussians model calibrated to standard ECG paper (25 mm/s, 10 mm/mV), so the tool ships as one HTML file with no server, no build step for the user, and no network access.

**Live:** https://andrewjfiore.github.io/ecg-toy/
**Offline:** download `index.html` and double-click it. That is the whole application.

> Educational use only. The waveforms are modeled, not recorded from patients. This is not a diagnostic tool and carries no clinical warranty.

## First run

A six step guided tour opens automatically the first time the app is used, pointing at the vignette, the diagnosis options, the mode selector, the lead grid, the submit button and the Progress tab. It is skippable, keyboard navigable (arrows, <kbd>Enter</kbd>, <kbd>Esc</kbd>), and remembered in `localStorage`, so it appears once.

The **?** button in the header opens brief written instructions and a **Take the guided tour** button, so the walkthrough can be replayed at any point. Both are covered by `ecg-file-check.js`, which asserts the tour auto-opens on a fresh profile, advances and reverses through all six steps, marks itself seen, replays from the help dialog, and keeps the spotlight aligned with the popover on screen at every step.

## How scoring works

This is the part worth being precise about.

**A case is scored correct or incorrect on the diagnosis alone.** Nothing else moves the session score, the streak, the per-diagnosis accuracy, or the weighting that decides which case you see next.

Two modes change *what is asked*, never *how it is graded*:

| | Easy | Hard |
|---|---|---|
| Pick the diagnosis (5-option MCQ) | required | required |
| Call each of the 12 leads normal/abnormal | optional scratchpad | required before you can submit |
| What sets correct/incorrect | diagnosis | diagnosis |
| Lead reading | not reported | reported separately, never scored |

In hard mode the submit button stays disabled until all 12 leads carry a call, and it tells you how many are outstanding. Your lead calls are then graded against the answer key and shown in their own block, below the teaching and visually outside the verdict, with the accuracy tracked in its own column in Progress. It is feedback, not a grade.

### The per-lead answer key

Hard mode needs to know which leads are genuinely abnormal in each case. It does **not** use the `keyLeads` field: that is a short "where to look" teaching pointer, and treating it as an abnormal-lead map teaches wrong medicine. Atrial fibrillation lists `II, V1`, but absent P waves and irregular RR are visible in all twelve leads; the same is true of VF, complete heart block, bundle branch blocks and long QT.

So `ecg-lead-truth.json` is derived from the engine spec itself:

- **Global** properties (`spec.rhythm`, `spec.qrsWidth`, and `spec.flags` such as `noP`, `peakedT`, `longQT`) are applied inside `computeLead()` to *every* lead, so they make all twelve abnormal.
- **Focal** properties (`spec.leadOverride[lead]`, `spec.precordial[lead]`, and limb leads derived by projecting the ST/axis vectors onto the hexaxial reference) make specific leads abnormal, including reciprocal change.

Every lead call was then reviewed against two independent checks: whether a cardiologist would sign it as an answer key, and whether the engine actually renders the finding at a magnitude a reader can perceive in a small panel. Leads that are genuinely reader-dependent, or where reviewers disagreed, are marked `either` and **excluded from grading entirely** rather than guessed at. Grading only what is defensible is the point.

### QRS width calibration

The Gaussian QRS template renders about 0.52x its nominal duration once the tails fall below what a reader can see. `spec.qrsWidth` was therefore not the rendered width: a normal 90 ms QRS drew at ~47 ms, and RBBB, LBBB and the complete-heart-block escape all drew **narrow** (66-76 ms) in the eight leads carrying no `qrsComps` override, inverting the defining feature of a bundle branch block. `QRS_CAL` corrects this so rendered duration matches the spec across the range (measured ratio 0.98-1.01; see `measure-timing.js`).

Two things followed from that fix. The ST bump and the T wave are now positioned relative to the **J point** (`ECG.qrsEndMs`) rather than fixed offsets from the QRS onset, so a wide complex lengthens QT instead of eating into the ST segment. And the `widthScale` multipliers on the VT and torsades event trains were removed: they had been compensating for the narrow template and would otherwise double-count, rendering a ~340 ms complex.

## Clinical vignettes

Each diagnosis carries **three interchangeable vignettes**, picked by the case seed, so meeting the same diagnosis twice does not mean meeting the same story twice. A student cannot learn the presentation instead of the tracing.

They are also written so the vignette does not answer the question. The original set gave the finding away in 19 of 30 cases: "PR interval measures 260 ms", "coved ST elevation in V1-V2", "QTc 520 ms", "constant PR with intermittent dropped beats". A student could score well on those without reading a single ECG. Vignettes now give the clinical setting and let the tracing carry the diagnosis, so where a lab value *is* the diagnosis the cause is given instead (a missed dialysis session rather than a potassium of 7.4).

`validate-vignettes.js` enforces both properties: at least three distinct vignettes per diagnosis, and none containing interval or morphology language, lead names, a named rhythm or syndrome, the diagnosis's own words, or a telltale lab value.

## Case selection

Every diagnosis appears once before any repeats. After that, **Case mix** controls the draw:

- *Weak first* (default) draws weighted by weakness, so a diagnosis you keep missing comes up about 3x as often as one you have mastered. Accuracy is Laplace-smoothed (`(correct+1)/(seen+2)`) so a single miss is not a permanent 0%, and the weight has a floor so mastered diagnoses stay in rotation.
- *Even coverage* always draws from the least-seen diagnoses, ignoring accuracy.

Weighting reads diagnosis accuracy only. Lead reading never influences which case you get.

## Diagnoses covered (30)

Normal sinus, sinus brady/tachy, AFib, atrial flutter, SVT, VT, VFib; first-degree AV block, Mobitz I/II, complete heart block, RBBB, LBBB, WPW; anterior/inferior/lateral STEMI, posterior MI, NSTEMI/ischemia; LVH, RVH; hyperkalemia, hypokalemia; pericarditis, Brugada, PE/right-heart strain (S1Q3T3), long QT, torsades, digitalis effect.

## Reference library

The **Reference library** tab holds 44 real 12-lead ECGs from Wikimedia Commons, reused under their original licenses. These are not synthetic and not original work. Each image is credited to its author with a linked license and a link back to the source; most are CC BY-SA, which requires that any onward reuse keep the same license. See [CREDITS.md](CREDITS.md) for the full list.

Every image was checked against what its Commons source actually says it depicts. Fourteen did not match. Nine were **relabeled** to the source's own description, which in several cases reverses the original caption: the file we shipped as "Pericarditis" is described by its source as an acute myocardial infarction, the "Brugada" file is categorized as ARVD, and the "Lateral STEMI" is an inferior STEMI. Five were **dropped** because the source states no diagnosis at all, or because the image is simulator output rather than a real recording. Relabeled files were renamed to match. Nothing in the library is captioned with a diagnosis its source does not support.

## Progress

Saved in `localStorage` under the `ecg.*` namespace, with export / import / reset in the Progress tab. Imported files are treated as untrusted: every field is coerced to a number and unknown diagnosis ids are dropped.

## Development

The single source of truth is `ecg-engine.js`. Everything shipped is generated from it, so never hand-edit `index.html`.

```
node build.js          # inline engine + library index + answer key -> index.html, ecg-qa.html, ecg_cases.json
node build.js --deploy # also copy into the sibling cvs-review platform
node ecg-tests.js      # medical assertions: ST vectors, reciprocals, axis, morphology
node validate-truth.js # answer key vs engine: no lead may be 'normal' under a global abnormality
node validate-vignettes.js # 3+ vignettes per diagnosis, none naming the finding
node gen-credits.js    # regenerate CREDITS.md from ecg-library/index.json
node ecg-file-check.js # headless file:// smoke test, incl. the scoring-separation invariant
```

| File | Role |
|---|---|
| `ecg-engine.js` | synthesis engine + 30-diagnosis catalog (Node-exportable, single source of truth) |
| `ecg-trainer.template.html` | trainer template; `build.js` inlines the engine into it |
| `ecg-qa.template.html` | QA harness template |
| `ecg-lead-truth.json` | per-lead answer key for hard mode (derived from the engine spec) |
| `ecg-library/index.json` | reference image metadata: condition, author, license, source |
| `index.html` | **generated** - the shipped trainer |
| `ecg-qa.html` | **generated** - renders every diagnosis in a grid for eyeballing realism |
| `ecg_cases.json` | **generated** - case bank derived from the catalog |

`ecg-file-check.js` asserts the scoring contract directly: it runs cases with every lead deliberately marked abnormal and fails the build if the session score, streak, or correct count moves by anything other than the diagnosis.
